# HeliumBoom 个人主页与技术博客

## 目的与已知要求

用户要求为 `HeliumBoom/HeliumBoom.github.io` 选择常用博客基础，完成个人主页与技术博客并提交相关代码。用户已选择简洁阅读风格：留白、清晰排版、少量强调色。远程仓库为空，默认分支 main；本地仓库无文件和提交。

## 方案比较与决定

| 方案               | 优点                                                              | 本项目取舍                                         |
| ------------------ | ----------------------------------------------------------------- | -------------------------------------------------- |
| Astro + AstroPaper | Markdown/MDX、静态搜索、标签、归档、RSS、明暗模式；可独立修改主页 | 采用。适合主页与博客并存，现有 Node 环境可直接开发 |
| Hugo + PaperMod    | Go 单文件工具，静态博客生态成熟                                   | 可行，但需要增加 Hugo 环境，定制使用 Go 模板       |
| Hexo               | Node.js 博客生成器，Markdown 和主题机制成熟                       | 可行；本次偏好可直接组合页面组件的 Astro           |
| Jekyll             | GitHub Pages 原生构建支持，Markdown 与 Liquid 模板成熟            | 可行，但本地需要 Ruby 环境                         |

这是实施者基于用户授权作出的技术选择，不是用户指定的框架。来源核对于 2026-11-11：

- https://github.com/satnaing/astro-paper
- https://docs.astro.build/en/guides/deploy/github/
- https://gohugo.io/host-and-deploy/deploy-to-github-pages/
- https://hexo.io/docs/
- https://jekyllrb.com/docs/github-pages/

AstroPaper 上游快照：`6f61e2dc0e45bbcefc05f4055f293cd7f81bcb03`，版本 `7.1.0`，MIT 许可。保留许可证和来源记录，不把上游示例文章伪装为本站文章。

## 页面与内容

- `/`：HeliumBoom 身份、简短介绍、文章入口、最新文章、GitHub 与 RSS 链接。
- `/posts/`、文章详情、`/tags/`、`/archives/`、`/search/`：复用主题成熟能力，界面中文化。
- `/about/`：简单站点与作者介绍，仅使用已知账号身份，不捏造履历或项目。
- 发布一篇关于本站技术选择与写作流程的原创起始文章。另提供仓库内写作说明；不生成虚构的历史文章填充页面。
- 白/暖灰底、深色正文、小面积青绿强调；正文使用系统中文字体，支持深色和移动端。避免依赖外部字体服务。
- 使用 `zh-CN`、`Asia/Shanghai`，站点根地址 `https://heliumboom.github.io/`，不配置仓库名子路径。
- 保留代码高亮、目录、草稿过滤、RSS、sitemap、规范链接和社交元数据；社交链接只配置真实 GitHub。

## 范围和约束

静态站点；无后端、登录、数据库、统计和评论服务。本次不增加个人履历、联系方式或私人项目资料。动态 OG 若需要外部字体，改用本地生成的本站分享图。保持主题结构可维护，依赖采用锁文件。

GitHub Actions 在 main 推送时检查、构建、索引并发布 Pages；PR 只构建检查。使用仓库自带的 GITHUB_TOKEN，最小权限；无需自建密钥。用户已授权代码提交，完成后正常推送到这个空仓库的 main，不使用强推。如现有凭据允许则设置 Pages 使用 Actions 并跟踪首次部署，否则准确记录所缺操作。

## 验收

类型检查和生产构建成功；构建产物覆盖首页、中文文章、标签、归档、搜索、关于、404、RSS 和 sitemap。确认站点链接正确、没有模板作者/示例文章残留、草稿和未来文章不进入公开列表。浏览器检查桌面/窄屏、明暗切换、中文搜索与文章导航。提交前独立代码检查；推送后核对远程提交和部署状态。

排版尺寸、组件细节、依赖安装方式、检查脚本形式由实施者决定。
